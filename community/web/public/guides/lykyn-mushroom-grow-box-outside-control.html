Outside control for a Lykyn mushroom grow box

Updated 2026-11-05

Outside control means we talk to a Lykyn through its existing app and cloud, and we leave the stock software on the box. When our unit arrives we will record what the official app sends, write it up in a public adapter repo, and only then try a dry run. None of that is proven yet. This is not a reflash, which is how OpenShrooly runs a Shrooly chamber.

What does outside control mean?

Outside control is a way to read and set a chamber without replacing the software that shipped on it. The official app stays the source of how the box talks. We watch that path, write down the reads and writes, and later wrap them in a small adapter so a grow profile can drive the same settings.

For a Lykyn that means:

  • Stock software stays on the box. We do not flash it. We do not ask you to open it.
  • The official app and cloud stay in place. The adapter, once it exists, would sign in the same way the app does, on your own computer.
  • Credentials stay with you. Email and password would live as environment variables on the machine that runs the adapter, the same way the AC Infinity adapter does. Shroom Labs would not store them.
  • A dry run comes first. A first tool should print the plan and write nothing, until someone adds an apply flag on purpose.

That is the plan. It is not a working adapter. Read Lykyn for mushrooms for the arrival status.

What will we look at when the box arrives?

The unit is in transit. Until it is on a bench here, there is nothing to record. When it arrives we will set it up the way Lykyn describes on the official Lykyn site: water in the reservoir, a fruiting block on the tray, species picked in the app. Then we watch three links.

  1. Phone to box. What the official app sends over the local network, if it talks to the box directly at all.
  2. Phone to cloud. What the app sends to Lykyn's servers to read humidity and temperature, and to change humidity, fans, light, or the species preset.
  3. Box to cloud. Whether the chamber reports readings on its own, and how often.

We will write down field names, units, and which settings the app actually changes. Those notes go in the Shroom Labs Lykyn adapter on GitHub. The repo is public on purpose. Credentials stay out of it.

We are looking for the same kinds of things a grow profile needs: humidity, temperature, fresh air, and light. If those can be read and set from outside, a later adapter can map a free profile onto them. If they cannot, this guide will say so and you should keep using the Lykyn app by hand with the numbers from the grow profiles.

Nothing in that list is mapped yet. Treat every endpoint, field, and unit as unknown until a note lands in the repo with a date.

What is untested?

All of it. Outside-control validation has not started. The public repo holds a short pitch, not a tool you can run.

  • Whether a sign in from software we write is accepted.
  • Whether live humidity and temperature can be read from outside.
  • Whether humidity, fans, light, or a species preset can be set from outside.
  • Whether those writes match what the official app shows after they land.
  • Whether a Lykyn holds fruiting humidity for lion's mane, oyster, or shiitake the way the profiles ask.
  • How a Lykyn compares to a Shrooly chamber on the same block. That comparison is the planned grow log, and it has not started.

Until those are checked, do not claim a Lykyn is supported. The chambers table marks it Arriving. The grow log marks it arriving, outside-control validation pending. Both stay that way until someone here has read and set a real unit from outside.

How is this different from flashing a Shrooly chamber?

OpenShrooly replaces the stock software on a Shrooly chamber. You install it from Chrome or Edge with a USB-C cable in about 5 minutes. After that the chamber runs on your own Wi-Fi from a local web page, and the Shrooly app is not in the path. That is a reflash.

The Lykyn plan is the opposite. The stock software stays. The official app stays. We build a translator that sits outside and speaks the same language the app already speaks. If Lykyn changes that language, the adapter can break. If it breaks, you still have the official app and can set the box by hand from a grow profile.

Terrashroom is on the flash path, like a Shrooly chamber: community ESPHome firmware, untested on real hardware. AC Infinity is on the outside-control path, like Lykyn: a cloud adapter written from a community integration, also untested on a real controller. Lykyn is earlier than AC Infinity. AC Infinity has adapter code and tests against a fake server. Lykyn has a repo and a plan.

Can I use a grow profile on a Lykyn today?

Yes, by hand. Open the species in the grow profiles, copy the humidity, temperature, fresh air, and light for the stage you are in, and set the official Lykyn app as close as it allows. The app's species presets are Lykyn's, not ours. We have not compared them to the profiles.

Automatic apply from Shroom Labs is the adapter's job, and that job has not started. The grow timeline calculator still helps you pick stage dates while the box runs on its own controls.

Shroom Labs is not made by Lykyn. Product steps quoted above come from the official site. If you own a box and want to share what the app lets you set, use the contact page on this site and pick A chamber.

FAQ

What does outside control mean?

We talk to the Lykyn through its existing app and cloud, and we leave the stock software on the box.

Will Shroom Labs flash the Lykyn?

No. The plan is outside control. Flashing is how OpenShrooly runs a Shrooly chamber, not how we plan to run a Lykyn.

Can I use a grow profile on a Lykyn today?

Yes, by copying the numbers into the official Lykyn app. Shroom Labs cannot apply a profile to a Lykyn yet.

Where is the adapter code?

In the public lykyn-adapter repo on GitHub. It is a pitch and a place for notes. Nothing in it talks to a real Lykyn yet.
